# v0.6 Milestone 1 — Weekly Activity Generator

Base archive: e8da92afea5d2daae63e04738e344d068f5bf6c0. Apply changed files to the approved v0.6 feature branch, not directly to main.

- Six independently selectable defaults, including Assignments (hand-ins) and Exercises (self-study).
- Course header action, optional new-course setup, custom activities, all/specific teaching weeks, live counts, save and error feedback.
- Up to ten activity types and thirty teaching weeks (300 activities). Assignments appear in Tasks with no fabricated deadline; exercises are not actionable until explicitly scheduled or included in Tasks. New exercise kind is additive; deploy backend and frontend together. Existing records remain unchanged.
- Single authenticated generation request. The existing workspace transaction validates course scope and skips matching names (case and whitespace normalized). Manual weekly creation and rename also reject new matching names. Intentional recurrence successors keep their existing behavior; previously stored duplicates are not modified. A name change can make an activity eligible for generation again. Legacy combined `Assignments / Exercises` titles are not treated as either new exact name; review those manually.
- API response includes created and skipped matching records, so a retry can recover newly saved rows missing from the browser. Existing cached rows are not overwritten by skipped matches, and the snapshot coordinator retains affected IDs during an in-flight refresh. Other-device edits still use existing refresh behavior.
- No Firebase rules, indexes, credentials, Drive permissions, Vercel settings or database migration required. Existing users can retain all previous records. The backend scans the user's existing items once per generation; the scan is reused to avoid one point read per generated item. No changes to the PDF viewer or Focus timer.
