# Study Hub v0.5 — pre-Production code audit (22 Nov 2026)

## Baseline and limits

Audited the latest available local v0.5 working copy built from the previously provided `studyhub-v0.5-performance-responsive-ui-changed-files.zip` and its parent source snapshot. **This is not a live read of the current remote `main` or Vercel deployment.** Do not overwrite newer GitHub commits without reviewing the diff. RepLap is outside scope.

The audit covers Next.js page state and navigation, Tasks/Calendar drag-and-drop, Course Planner forms, task projections, Firebase Auth/API wiring, Python REST endpoints, SQLite/Firestore persistence, recurring task creation, Focus session storage, Google Drive OAuth entrypoints, Vercel configuration, CI checks, and CSS responsiveness. It includes code inspection and local tests, not a full live-browser or production database security assessment.

## Release fixes supplied

1. **Deadline-safe planning (correctness, high):** Calendar drops now reject dates later than a task's deadline, including direct API writes; the due date remains unchanged. The API also rejects a changed due date that would precede an existing planned date. The *same day* is allowed. This is validated for new tasks and date changes, not mere completion of older records whose dates were already inconsistent, preserving existing data compatibility.
2. **Calendar drag/hover feedback (UX, medium):** Track the actively dragged task, highlight only the hovered date, display a high-contrast mint valid target vs coral invalid target, and show a visible invalid-date explanation. Reset hover state after the drag ends. Mobile uses date-picker constraints and server validation instead.
3. **Odd-numbered Home course cards (UX, medium):** The third card uses a full-width compact horizontal layout at desktop/tablet widths, rather than leaving a blank grid slot. The existing single-column mobile layout is preserved.
4. **Course Workspace planning (correctness):** The Week checklist date picker and course activity creation form enforce the same deadline rule, including “Plan for today.”

No migration, dependency changes, Firebase rules, secrets, environment settings, or production data mutations are included.

## Audited areas and findings

| Area | Assessment | Remaining risks / follow-up |
| --- | --- | --- |
| Task creation/editing | Shared Item ID, typed API validation, scoped updates, optimistic completion and rollback are implemented; dates now constrained for new changes | Confirm UI works with real Firebase on Preview; task mutation race across two devices is last-write-wins |
| Calendar and Home navigation | Standalone Calendar, inline Home agenda, course/week links and direct task highlighting are present | Drag feedback needs manual desktop/browser verification; mobile must use Edit instead of drag |
| Home and responsive layout | Two-column course cards, compact third-card adaptation, light/dark theme overrides | Visual acceptance required on 1024px, 1440px and mobile; source-only checks do not substitute for screenshots |
| Initial workspace load | Six Firestore collections are read concurrently; initial error state is distinguishable from empty data | Fetching complete session/resource history on every full snapshot will eventually scale poorly |
| Post-mutation speed | Local cache updates avoid full snapshot reloads for common operations; task checkbox UI is optimistic | Measured network latency/Firestore costs need DevTools `Server-Timing`; cannot claim a target speed without measurement |
| Authentication/isolation | Cloud backend requires Firebase auth and an allowed UID/email; Preview service account project ID is checked against a different configured Production ID | Confirm actual Vercel environment variables, rules and authentication in Preview; do not point Preview at Production |
| Google Drive | OAuth tokens encrypted and stored server-side; Preview Drive OAuth disabled by default | Live OAuth/Goodnotes PDF workflows not tested in this local audit |
| Recurrence | Successor IDs are deterministic, reducing duplicates on retries; weekly and monthly tests pass | Recurrence writes are not transactional across multiple simultaneous devices; 31st-of-month schedules can shift to 28th after February (review desired semantics later) |
| Focus | Sessions persist, pause/resume/finish validations and personal-task linkage have tests | Starting from two tabs simultaneously is a read-then-write race; address with a transaction/active-session sentinel before multi-device heavy use |
| Firestore latency | Snapshot reads are threaded concurrently; auth revocation verification is offloaded to a thread | Many other `async` API handlers still make synchronous Firestore SDK calls, potentially blocking the Python event loop during overlapping operations; refactor after stable release, benchmark first |
| Rendering | Clock ticks every 30 seconds while idle and every second with active focus; simple CSS rather than heavy chart dependencies | Active timer still rerenders the top-level Page; consider separating timer subscription/component if profiling shows frame drops |
| Deployment/CI | GitHub Actions specifies Python 3.12, Node 22, pytest, `tsc`, `npm test`, and `npm run build`; Vercel routes `/api/*` to Python | Actual current CI/Preview/Production commit, build, Firebase auth and page performance cannot be verified offline |

- Frontend: **48/48 Node test cases passed**, including new deadline helper and source-wiring checks.

1. Confirm `origin/feature/v0.5-tasks-calendar` is the intended commit and GitHub Actions backend + TypeScript + npm tests + Next.js build all pass.
2. With a task due **26 Nov 2026**, drag onto **25 Nov** and **26 Nov** (both allowed) and **27 Nov** (red blocked target, no write). Refresh and verify original deadline/plan persist. Repeat using Tasks Edit and Course Week Plan.
3. Drag across adjacent calendar cells and off the grid; no stuck highlights or accidental drops. Test Chrome and mobile date editing. Check contrast in light and dark themes.
4. On Home, verify **3 scheduled courses** render as two standard cards plus one compact full-width third card; verify 1, 2, 4, 5+ courses and narrow screens. All links must open the right course/week.
5. Verify overdue/due-only items, task completion, recurrence, and a multi-week course card after refresh. Confirm that the Home, Tasks, Course and Calendar checkboxes stay consistent.
6. Start/pause/finish Focus, refresh during an active session, and test linked personal and course tasks.
7. Check first login, sign-out/sign-in, authentication recovery, PDF open/bookmarks, and no Preview requests or credentials targeting Production Firebase.
8. Use DevTools Network: compare complete `/api/snapshot` duration and single task `PATCH`, including `Server-Timing`. Ensure a simple checkbox action does **not** issue a new `/api/snapshot` request.
9. Inspect the **deployed Preview** on desktop/mobile and confirm no browser console errors. Only after your approval, merge the verified commit to `main`.

## Release decision

**Code-audit result: candidate for Preview acceptance, not yet certified Production-ready.** The identified calendar and course-grid problems are addressed locally without a schema change. The highest remaining gate is CI/Preview verification, not another speculative redesign. Keep backend transaction/concurrency and large-history optimizations out of this last-minute patch unless a reproducible Preview failure justifies them.
