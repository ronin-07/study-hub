# Study Hub v0.4 — Course Workspace and release checklist

## Overview

This release is an additive change over v0.3.1. It does **not** require resetting or migrating production Firestore records. No changes to RepLap or its Firebase project.

- **Semester & course setup:** optional `semesters` collection with create, rename and delete (blocked while containing courses); old courses remain grouped by their legacy `semester` string. Course edit supports code, title, teaching-week count, exam date, goals and semester. Course deletion requires empty linked data.
- **Week editing:** topic and objectives now editable; 1–30 weeks per course. You cannot reduce the week count while later weeks have linked data.
- **Study checklist:** lecture, notes, reading, revision and assignment activities; reading chapters/page ranges; linked tasks use the *same item record*.
- **Linked PDFs:** multiple resources can belong to one lecture activity; add DTU Learn links and connect Goodnotes Drive-backed PDFs, or attach previously linked files later. PDF associations are validated to be from the same course/week.
- **Reading workspace:** native browser PDF viewer in a split layout with course-week checklist, quick focus shortcut, zoom controls, explicit per-resource page bookmark and sibling resource switching. It does not track scrolling automatically and native PDF search depends on browser capabilities. Pages marked via the controls are persisted. Goodnotes annotations remain edited in Goodnotes.
- **Exam preparation:** course-wide revision tasks independent of teaching weeks.
- **Refactor:** reusable web components; additive API router for workspace edits.
- **Private cloud hardening:** Firebase authentication and Firestore allowlist preserved, encrypted Drive tokens remain server-side, OAuth state one-time challenge, preview Firestore environment rejects a production project, Drive integration disabled in previews unless explicitly enabled.

## Isolation and deployment

1. Keep `main` as the Vercel **Production** branch. Create `feature/v0.4-course-workspace` from the currently deployed v0.3.1 branch.
2. Commit the source on this feature branch and push to GitHub. The GitHub Actions workflow validates the Python API and checks/builds Next.js. Vercel normally creates a Preview deployment for non-production branches; it must **not** use production secrets or production Firestore.
3. Create a separate Firebase project for Preview (or do not provision a working Preview until one exists). On Vercel, scope Preview environment variables separately. Do not select “All Environments” when entering service-account credentials.
4. Preview backend requires `VERCEL_ENV=preview`, `STUDY_HUB_PREVIEW_FIREBASE_PROJECT_ID=<preview-project-id>`, `STUDY_HUB_PRODUCTION_FIREBASE_PROJECT_ID=<production-project-id>`, and a `FIREBASE_SERVICE_ACCOUNT_JSON` whose JSON `project_id` matches the preview project ID. Both IDs must differ. Missing/mismatched configuration fails closed on startup.
5. Preview must use **Preview Firebase Web SDK config**, `STUDY_HUB_AUTH_MODE=firebase`, `STORAGE_BACKEND=firestore`, and `STUDY_HUB_ALLOWED_EMAIL` restricted to your login. Add the preview branch URL to Preview Firebase Auth authorized domains if Firebase Google sign-in is tested on Preview; each host may require adding its domain.
6. **Do not copy** production `GOOGLE_CLIENT_SECRET`, `OAUTH_ENCRYPTION_KEY`, `APP_SIGNING_SECRET`, or `FIREBASE_SERVICE_ACCOUNT_JSON` into Preview. Drive OAuth is intentionally disabled in Preview by default. For testing Drive changes, use a separate OAuth client and test account and explicitly set `STUDY_HUB_ALLOW_PREVIEW_DRIVE_OAUTH=true` with separate credentials and callback URI matching the selected Preview URL.
7. Review the Preview deployment and run the acceptance tests below. Only merge after checks pass; merging to `main` triggers the Vercel production rollout.
8. Ensure existing v0.3.1 records remain visible after the merge. Do not upload `.env` files or reset Firestore. When creating a new Firebase project, publish `docs/firestore.rules` **only to the dedicated Study Hub Firebase project**.

## Environment variable additions (Preview only)

| Variable | Value |
|---|---|
| `STUDY_HUB_PREVIEW_FIREBASE_PROJECT_ID` | Preview Firebase project ID |
| `STUDY_HUB_PRODUCTION_FIREBASE_PROJECT_ID` | Existing production Firebase project ID |
| `STUDY_HUB_ALLOW_PREVIEW_DRIVE_OAUTH` | Omit or `false` by default |

Production needs **none of these new variables** and should retain its existing credentials. All Drive secrets remain server-only. The deny-all Firestore rules prevent web SDK direct reads/writes; the verified backend uses Firebase Admin SDK with server IAM permissions.

## Acceptance tests (in Preview, with safe test data)

- [ ] First load: sign-in succeeds with preview Firebase and unauthorized account is blocked.
- [ ] `/health`: `status: ok`, `storage: firestore`, `auth: firebase`.
- [ ] Add a semester; edit its name; add a course to it; edit exam date, goals and week count; verify reload persists.
- [ ] Create Week 10 and edit its topic/objectives. Attempt shortening a course with Week 10 data below 10 weeks: error must be clear, records unchanged.
- [ ] Create a lecture, reading task (chapter and page range), revision task and assignment. Plan and due dates are independent.
- [ ] Edit a linked assignment in Tasks; complete it in Study; verify both views update and persist.
- [ ] Add an exam-preparation task (no teaching week), see it in Tasks, and complete it.
- [ ] Link original slide and annotated PDF to the same lecture. Switch between them from the PDF reading side panel.
- [ ] Open a real Drive PDF **in Production only** (or an explicitly isolated Drive Preview), change the bookmark, reload, verify its saved page.
- [ ] Try linking a PDF to an item in a different week: backend returns 422.
- [ ] PDF on a phone: reader has navigation, accessible close, study sidebar, and no horizontal UI overflow.
- [ ] Google OAuth: complete connection, refresh token, and ensure two visits to same callback state do not reuse it. The old sign-in remains authorized in Production.
- [ ] Delete a course containing a lecture/resource and confirm deletion is blocked (409).
- [ ] Confirm no production Firestore documents changed during Preview testing.

## Tests and builds

```powershell
# In backend:
py -m pytest -q

# In web (run on your own machine if desired, or let GitHub Actions do it):
npm install
npm run lint       # current project script performs TypeScript checking
npm run build
```

The GitHub workflow executes the same checks after you push. `web/package-lock.json` is not bundled because this environment cannot reach npm; once `npm install` succeeds, commit the generated lockfile to obtain reproducible dependency installs, then switch the workflow to `npm ci`.

## Limitations

- This release uses the browser's embedded PDF viewer; it does **not** offer PDF.js text layer or synchronized highlights. Searchability depends on the source PDF and browser. The bookmark is explicit, not automatic scroll tracking.
- Live DTU Learn API imports and AI-generated revision materials are out of scope.
- The 50 MB Drive PDF preview ceiling still applies.
- Google Drive scans are manually triggered; they are not periodic server-side jobs.
- Development preview without a separate Firebase project is intentionally non-operational; this protects Production.
