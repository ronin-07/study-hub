# v0.6 safe resource removal

Standalone follow-up to M3A, Home Progress Fix and safe course deletion. No configuration or migration changes. The old DELETE endpoint remains safe for older clients (blocks linked resources and recorded exam attempts). The new removal preview is read-only; the confirmed POST recomputes a hash of current resource and affected items and atomically clears direct item resource IDs and deletes only the Study Hub resource. Reverse item attachments disappear with the resource. Original external files, Drive index, activities, Focus and other resource records remain. Saved page position disappears with the removed resource entry; recorded exam attempts block removal. Archived courses, cross-course legacy references, stale previews and oversized transactions are rejected. Limit 450 affected writes including deletion, and estimated 4 MiB serialized source data. Resource linking via PATCH participates in workspace transaction to prevent races. Frontend updates affected cached item records and deletes the resource in one operation, preserving in-flight snapshot changes; blocks overlapping optimistic completions. No extra reads during ordinary navigation. Preview and confirmation each query linked activities; confirmed deletion writes the affected items and workspace guard, deletes one resource. No full snapshot on normal success.

Manual checks: cancel; remove unlinked resource; remove multiply linked resource; verify study records, progress, dates, notes and original file; check exam-attempt blocker; verify no snapshot on success; refresh; light/dark/mobile. Deploy backend and frontend together (backend first if separate).
