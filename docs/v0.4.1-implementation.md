# Study Hub v0.4.1 — Semester navigation, archiving, shared Course Library

## Status

Implemented on a **separate local feature branch** based on the v0.4 development branch. Do not merge into `main` until Vercel Preview and GitHub Actions checks pass. No production Firebase, Vercel or Google Drive account was modified by this source update.

## User-facing changes

- **Semester-first Academic Planner.** Select a semester once; the course rail filters to it. The course picker cannot display a course belonging to another semester. New and edited courses use **one** semester dropdown that defaults to the selected semester.
- **Legacy course compatibility.** Courses that only have a `semester` name remain visible. Registering a semester under that name automatically adopts those courses; renaming the semester updates both formerly linked and legacy courses consistently. Existing Firestore IDs and week records are preserved.
- **Edit, archive, restore.** Courses can be edited and moved to another semester. Archive hides the course from active navigation and removes its unfinished tasks from Today/Tasks, but preserves all course weeks, lecture items, resources, deadlines and focus history. The archived list allows read-only viewing and restoring the course. **Permanent course DELETE now returns 405**; the UI no longer offers destructive course deletion. Archiving is blocked while that course has an active focus session.
- **Shared Course Library.** `Resource.week_number=null` means the document is shared by the entire course. Textbooks, whole-course Goodnotes notebooks and reference PDFs are linked **once**. Existing resources with numbered weeks stay exactly where they were; no automatic relocation/migration.
- **Week resources.** Lecture slides and annotated lecture materials can remain week-specific. The resource editor can move a week-specific PDF into Course Library or back (subject to reference validation), without copying the source file.
- **Reading references.** `Item.resource_id` can refer to a shared book/notebook, with a separate chapter/page range for each teaching week. This reuses one PDF record across multiple reading or notes activities. It does not duplicate or edit the original Google Drive PDF.
- **Source selection.** Global Goodnotes Drive linking now offers *Course Library (all weeks)* or *one teaching week*; filename matching still requires review before linking. Handwritten notes and textbooks confirmed from suggested matches default to shared course scope.
- **Responsive workspace.** Semester and course navigation in a compact side rail on desktop, horizontal chips on mobile, course-week hero, focused tabs for Overview, Course Library, Week Resources, Study Tasks, Exam Preparation, and actionable empty states.

## Backend API changes

| Endpoint | Behavior |
| --- | --- |
| `POST /api/courses/{id}/archive` | Archives course, rejects active focus session |
| `POST /api/courses/{id}/restore` | Restores course, all existing data remains |
| `DELETE /api/courses/{id}` | `405`: permanent deletion disabled |
| `POST /api/resources` | Accepts `week_number:null` for shared resource |
| `PATCH /api/resources/{id}` | Can change `week_number` to/from `null`; rejects invalid item associations and conflicting cross-week references |
| `POST /api/items` | Accepts optional `resource_id` referencing a resource in the same course and (for weekly PDFs) week |
| `PATCH /api/items/{id}` | Can set or clear `resource_id`, with cross-course/weekly validation |
| `DELETE /api/resources/{id}` | Rejects if a study item references the resource; unlink first |
| `POST/PATCH /api/semesters` | Adopts/updates legacy same-name courses to prevent UI grouping drift |

**Archived courses:** editing courses, weeks, items and resources; deleting associated sessions or resources; and starting new focus sessions are blocked by the API until restore. A PDF reading-page bookmark may still be updated while viewing an archived course. Archiving does **not** delete or modify files in Drive, Goodnotes, or DTU Learn.

6. Merge only after automated and manual checks pass. No Firestore migration is needed, but take a backup/export before production release if you have valuable existing data.
