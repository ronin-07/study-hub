# v0.5 stability candidate — release audit (22 November 2026)

**Target branch:** `feature/v0.5-tasks-calendar`. Do not create a v0.5.1 branch or merge without approval.

**Source baseline:** uploaded `studyhub-starter-v0.1(1).zip`, Git commit `1d0465b` (v0.5 tasks/calendar). Verify that the actual remote branch has not advanced before applying these complete files; do not overwrite newer work.

## Changes included

- Weekly checklist activities can be scheduled to today or a selected date using the same item ID; the date can also be cleared. Clearing the plan leaves an actionable item in the unscheduled Tasks inbox. Already-completed items must be unchecked before scheduling. Linked book/notebook resource IDs are preserved and may be opened directly from Home and Tasks.
- The Calendar month arrows update both the visible month and selected-day agenda. Moving January 31 to February clamps to February 28 or 29. Selecting an adjacent-month calendar cell navigates to its month.
- Today's priorities include due-today, planned-today, overdue-due, and overdue-planned items, including planned work without a hard deadline. Upcoming excludes items already included in Today, and Home Upcoming deadlines excludes overdue deadlines.
- Backend marks due-only activities actionable. The frontend also handles previously stored due-only items with `is_task=false` without requiring a migration.
- Home no longer falsely displays a completed/empty workspace after its initial API request fails; users can retry. Refresh on return-to-tab plus a manual refresh button helps show changes made on other devices (this is **not** realtime Firestore listening).
- Home course card no longer claims to be the last-opened course. Home priorities show up to six tasks with a link to the rest.
- Prevent duplicate submissions for Week and Add Activity forms. Session review caps confirmation at the backend's 24-hour per-session maximum and explicitly explains timed modes are targets, not auto-stop Pomodoros.
- Frontend date/task logic tests added to CI. CI now uses `npm ci` with the existing lockfile.

## Compatibility

No new environment variables, external dependencies, or Firestore migrations. Existing model fields and IDs are preserved. The `is_task` behavior for due-only items is an additive compatibility fix. No changes to RepLap, OAuth credentials, Firebase projects, or the deployment config.

After local tests and Preview verification, request merge approval. Only then merge into `main`, verify the actual Production deployment commit and login, and perform a read/write task plus PDF smoke test in Production.
