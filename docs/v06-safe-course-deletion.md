# v0.6 standalone fix — Safe permanent course deletion

Apply after Milestone 3A and the Home Progress Fix. No migrations, new indexes, credentials or dependency changes.

Study > Archive course > Archived courses > select course > Delete permanently. The dialog requests an authenticated server preview, showing actual study item, saved week, resource, exam attempt and Focus session counts. Type `DELETE` and confirm. Original Drive files and their shared index are not touched. The semester and other courses remain.

Safety: only archived courses; full history is checked rather than the compact snapshot. Any Focus history or legacy cross-course reference blocks deletion. Preview fingerprint binds confirmation to the exact course and associated records; data changes (including archived PDF bookmarks) require a fresh preview. Existing unconfirmed DELETE endpoint remains disabled. Preview is read-only; confirmed deletion uses one existing workspace transaction and a conservative cap of 450 documents and 4 MiB serialized records (not an exact Firestore transaction-size measurement). If a transaction fails, no partial deletion is intended. Repeating a completed request returns 404 rather than modifying other data. The rare preview/confirmation operation scans the user's items, resources and sessions for dangling legacy references; the normal application has no additional reads. After deletion, a forced snapshot refresh reconciles the workspace. If refresh fails after a successful save, use manual refresh before retrying.

Deploy frontend and backend together. Test using a disposable course without Focus history; verify another course and shared Drive links remain intact, cancel/wrong confirmation, stale preview, restore, refresh and blocked deletion when history exists. Do not test against a real course you intend to keep. The test suite uses SQLite and a simulated Firestore adapter; live Firestore transaction behavior and visual layout must be verified separately.
