# Study Hub v0.5.1 — readability and Study/Tasks hotfix

## Scope
- Increase sitewide rem typography (18px desktop, 17px narrow mobile). Keep chapters/pages prominent while making the activity type and planned/due-date metadata slightly smaller.
- Edit a weekly activity's title, type, notes, chapter/pages, resource, dates, and Tasks visibility in the existing activity modal.
- Remove Quick Notes from Study Overview (no data deletion); retain notes as editable week activities.
- Show all shared course resources inside a keyboard-accessible, independently scrolling library card with a fixed visible footer.
- Support previous exam papers and exam solutions as shared resource types, including Drive linking, selected from the existing document/material-type dropdown (without extra shortcuts on the overview card).
- Separate **Remove from Tasks** from **Delete permanently** for course-week tasks. A new additive `hidden_from_tasks` boolean defaults to `false` for existing documents and overrides automatic task visibility without deleting their activity, dates, progress, or resource references.

No database migration, new service, Firebase rules change or credentials required.

## Preview data and production safety
- Production and Preview use distinct Firebase projects; never point Preview at Production credentials or IDs.
- There is no built-in Study Hub production-to-preview cloning endpoint. For realistic Preview tests, create a few representative records manually or perform a controlled admin-only copy of *non-secret* per-user workspace records into the Preview project, accounting for the different Firebase Auth UID. Do not copy Google Drive OAuth tokens or authorization secrets.
- Live Production testing after merge is possible, but validate the full build and non-destructive flows on isolated Preview first; keep real data backed up before testing delete or recurrence flows.
