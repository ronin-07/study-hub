# Study Hub v0.5.2 Stage A performance

Laptop Chrome is the primary performance target. Keep iPhone Safari in the release checks.

## Changes

- Reopening a PDF can reuse up to two recently viewed files held in tab memory, with a 64 MiB total limit and a ten-minute lifetime since the last validated open. Every reopen checks current Firebase and Drive access. The API returns an empty response when the verified checksum matches. Replacing the file fetches new bytes. Closing the reader releases its Blob URL. Signing out, changing accounts, or disconnecting Drive clears retained bytes.
- The native reader loads alongside the download when a PDF is opened. The filename, cancel control, and retry feedback remain immediately available. First-time downloads reuse one upstream HTTP connection for metadata and media, with the existing 50 MiB preview limit.
- Home starts with the shared workspace snapshot. Drive status and the index load when Resources is opened. Folder contents load when the browser is visible. A loaded empty folder is reused, and linked status comes from the current workspace so links and unlinks update filters across views.
- The desktop navigation comparison favored keeping Study and Tasks/Calendar in the initial bundle. Resources search remains local.

## Laptop profile

Five local headless Chrome trials per build at a 1440 × 900 viewport used an 8.47 MB, 520-page synthetic PDF and a repeatable mock API. Times below are medians. PDF timing ends when the native viewer frame mounts.

| Measurement | Original | Stage A |
| --- | ---: | ---: |
| Home workspace available | 135 ms | 127 ms |
| Home Drive requests | 2 | 0 |
| PDF first open | 1,080 ms | 1,076 ms |
| PDF reopen | 1,079 ms | 93 ms |
| PDF response body on reopen | 8.47 MB | 0 bytes |
| First Resources visit through index readiness | 6 ms | 141 ms |
| Repeat Resources visit through index readiness | 5 ms | 4 ms |

The original build started the Drive status and index ahead of the first Resources visit. Stage A moves that work to the first visit and avoids a folder request while the browser is hidden. Study and Tasks first-visit medians held at 12 ms and 6 ms. Initial gzipped JavaScript grew by about 0.5 KiB and initial CSS was unchanged.

In a separate two-trial screenshot check, the same page region became visible after 1.74 to 1.79 seconds on reopen in the original build and about 0.74 seconds with Stage A. Cold first-page paint was about 1.75 to 1.94 seconds across both builds.

Local verification passed 204 frontend tests, 118 backend tests, TypeScript, the local-auth production build, and the credential scan. Live Firebase and Drive measurements, chapter links in the user's textbook, and iPhone Safari remain Preview checks.

## Local checks

Run from the Git checkout after applying the archive. These commands use PowerShell, Python 3.12, and Node 22 as in CI.

```powershell
Push-Location backend
python -m pip install -r requirements.txt
$env:STUDY_HUB_AUTH_MODE = 'local'
$env:STORAGE_BACKEND = 'sqlite'
python -m pytest -q
Pop-Location

Push-Location web
npm.cmd ci --no-audit --no-fund
npm.cmd run lint
npm.cmd test
$env:NEXT_PUBLIC_STUDY_HUB_AUTH_MODE = 'local'
$env:NEXT_PUBLIC_API_URL = '/'
npm.cmd run build
Pop-Location
```

For an interactive local smoke test, run the API with `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` from `backend` in local SQLite mode. In a second PowerShell window, set `$env:NEXT_PUBLIC_STUDY_HUB_AUTH_MODE = 'local'` and `$env:NEXT_PUBLIC_API_URL = 'http://127.0.0.1:8000'`, run `npm.cmd run dev` from `web`, and open `http://127.0.0.1:3000`.

## Release checks

Use an isolated Preview already configured for Drive OAuth with test files. Verify the first and repeat visit to each section, task changes across views, Focus timer persistence and pause/resume, and Resources search, link, unlink, scan, and folder browsing. In Chrome on a laptop, open and reopen a Goodnotes PDF and an original 500+ page PDF under 50 MiB. Record click-to-first-visible-page and request bytes in DevTools. Confirm the repeat request returns a bodyless `304` for an unchanged PDF with a Drive checksum, a changed PDF downloads again, and denied access cannot display cached bytes. Exercise cancel, retry, switching PDFs, bookmarks, and chapter links. Check both themes, keyboard navigation, and the reader on iPhone Safari.

The backend change ships through the existing Vercel deployment. Firebase Authentication, Firestore schema, rules and indexes, Google Drive OAuth scope, Vercel configuration, and environment variables need no changes. Partial PDF loading remains a separate investigation.
