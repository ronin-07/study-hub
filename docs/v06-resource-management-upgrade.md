# v0.6 Resource Management Upgrade

Baseline: supplied v0.6 handoff, M1, M1 UI polish, M2, M3A, Home Progress Fix, Safe Course Deletion, Safe Resource Removal, applied in that order. This package contains only changed/new files. Apply after all prior fixes. No remote Git state or live Firebase was accessed.

## Implementation

- Compact activity rows explicitly center the checkbox, title and controls, including at desktop widths below 1181 px.
- Both existing association directions are supported: `Resource.item_id` (multiple weekly files for one activity) and legacy `Item.resource_id` (one directly referenced document, including shared books). The two directions are deduplicated when rendering. Existing files linked through the former field appear automatically; no migration or duplicate resource writes.
- Detach clears only the selected association(s) atomically, keeps the resource/bookmark, and updates affected cached records. Home/Tasks can open the existing direct reference or the first associated document; the weekly checklist displays all linked documents.
- Question papers and exam solutions are excluded from course and week resource listings and organized in Exam Prep. Existing resource IDs, bookmarks and attempts are retained. Existing weekly associations remain valid. A legacy weekly exam paper may be moved to course-wide Exam Prep through edit (detach a direct weekly attachment first) to enable dedicated practice Focus.
- Optional `exam_paper_id` on solution records only; same-course question-paper validation; multiple solutions can point to one paper. Unpaired solutions remain visible. A paper with paired solutions cannot be removed or converted to another kind until solutions are explicitly unpaired; recorded attempts retain their existing protection. Removing a solution preserves the paper, its attempts, other solutions and Focus history. Removal preview includes the paired paper and rejects a stale confirmation.
- Bulk mode in both Drive folder and discovered PDF lists, select visible up to 30, review individual course/week/type/attachment/paper settings, optional common settings. Filename-based week and exact normalized paper/solution suggestions are editable, not silently saved. Out-of-range weeks require correction. No matching activity results in an explicitly flagged week-only link. One authenticated atomic bulk request; identical links skipped, conflicting destinations rejected with no partial writes. Existing resource IDs returned and reused. The existing single-file workflow remains available.
- No new background requests, collections, dependencies, mandatory migration, Firestore rule edits or Vercel settings. New bulk and detach routes require a coordinated backend/frontend deployment. The extra pairing relationship lookup is used for removal; normal workspace loading unchanged. Each new unique resource still consumes an individual write. No Google Drive file modification/deletion routes are invoked.
