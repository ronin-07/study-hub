# Study Hub v0.5 — UI Polish 5: saving and notifications

## Scope

This is an **incremental patch on UI4a**, on `feature/v0.5-tasks-calendar` only. It does not alter API routes, Firebase schemas, the Study layout, the countdown timer, or existing task/progress/photo animations.

### Feedback behavior

- **Success**: compact toast in the top-right, below the global header; disappears after ~3.5 s. No toast is created merely by changing a week, pausing a Focus session, or checking a task.
- **Errors**: persist until dismissed. User input is kept in the open form; failed task delete no longer closes the editor. Individual task completion still rolls back on failed write.
- **Information**: 5.5 s if used. At most three notifications are visible. The queue deduplicates repeated titles and protects visible errors from being replaced by successes.
- **Screen readers**: status messages are `role=status`; error notifications are `role=alert`; dismiss controls are labeled.
- **Animations**: short slide/fade entrance, disabled under `prefers-reduced-motion`; fixed positioning avoids layout shifts. Light and dark schemes are supported.

### Operation coverage

- Semester/course/week create or edit, study activity and quick note save, course archive/restore, resource link/unlink, exam task create, task create/edit/delete/reschedule.
- Course archive shows a short **Undo** action (visible for ~8 seconds), which calls the existing restore endpoint. It does not undo other destructive operations automatically.
- End/review Focus confirmation shows the **actual saved focus duration**; pause/resume/start do not generate success notifications.
- Google Drive PDF linking has an item-specific `Linking…` spinner, folder selection confirms, scans show progress and total indexed PDFs, failed scans offer **Retry scan**, disconnect confirms.
- Save actions share a synchronous `mutationBusyRef` lock to prevent double-submissions within the same React render frame. Timer commands and optimistic task completion keep their pre-existing independent locks.
- A failed post-write snapshot refresh reports **Saved, but sync failed** and avoids prompting users to resubmit a potentially successful create.

### Validation performed in this package

- `cd web && npm test`
- `cd backend && python -m pytest -q`
- TypeScript syntax transpilation and CSS parse checks

A **complete** `npm ci && npm run lint && npm run build` still needs to succeed locally or on Vercel. Live Firebase and browser interaction verification remain required before merge.

### Preview acceptance checks

1. Save semester, course, week, quick note, activity, task, and resource; verify the button shows Saving and toast appears after the server response.
2. Double-click Save rapidly: create exactly one record.
3. Trigger a rejected save (e.g., duplicate course code): form and typed input remain, error persists until dismissed.
4. Archive a course then Undo: it returns to active courses; test after switching pages.
5. Save Focus: a success toast appears without affecting the countdown, while Pause/Resume do not show toasts.
6. Scan Goodnotes PDF folder: show spinner, correct indexed count and Retry on failure; link a PDF and observe the item-specific spinner.
7. Trigger failure of task completion: checkbox rolls back; error notification persists.
8. Verify dark/light and reduced-motion variants, narrow layouts, screen-reader announcements, and dismissal.
9. Confirm previously approved UI1–UI4a appearance and performance remain unchanged.
