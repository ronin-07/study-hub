# Study Hub v0.5.1 — Main follow-up (Questions and readability)

## Scope
- Removed the redundant paragraph beneath **Include in Tasks and Calendar** in the Study activity dialog. Kept the descriptive checkbox label.
- Added the **Questions** activity kind, including editing existing activities into this kind. Its existing `chapter` field is labeled **Question numbers** in the form and **Questions** in the weekly checklist. Example: `3,4,5.6,4.2.1` displays as `3, 4, 5.6, 4.2.1`.
- Normalized comma spacing in displayed chapter, section, and question references without changing persisted text. Improved numeric letter spacing for dotted identifiers.
- Added Questions to the course-linked task type choices, so the activity label is consistent throughout the app.

## Checks
- Backend API: Questions creation, update, reload, conversion from Reading and unchanged stored reference strings.
- Frontend: Questions selection/labels, reference display formatting, checkbox hint removal and CSS.
- Manually test the edit dialog, course progress, task visibility, long chapter/question references and page layout on desktop/mobile.
- Run `cd web && npm ci && npm test && npm run lint && npm run build` and `cd backend && python -m pytest -q` before pushing to `main`.

## Deployment
- **Frontend and backend redeploy required**: backend validation must accept `kind="questions"` when the frontend starts offering it.
- **No Firestore rules, indexes, authentication, Vercel environment variables, or data migrations** are needed. Stored existing items remain valid and unchanged.
- Since this is a direct-`main` follow-up, deploy only after local build verification; take note of the prior production commit, and use `git revert <commit-sha>` for a non-destructive code rollback if required. A Git revert does not undo Firestore writes made after deployment. **Important:** before reverting to a version that does not support `kind="questions"`, delete disposable Questions activities or convert any real ones to a supported older kind while the new backend is still deployed. Otherwise old API response validation and editing of those records can fail.
