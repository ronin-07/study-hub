# Study Hub v0.5 — Tasks & Calendar (first feature-branch iteration)

**Branch:** `feature/v0.5-tasks-calendar` — keep all subsequent v0.5 fixes and revisions on this same branch until acceptance. **Do not merge before Preview and CI pass.**

## What changed

- The previous inline Tasks UI has been replaced by `web/components/tasks-planner.tsx`.
- Four views: Today (planned today + due today + overdue), Upcoming (other open and unscheduled tasks), Calendar (month grid and selected-day agenda), Completed.
- Study and personal tasks use the **same** `items` collection and patch endpoint. Editing or completing a linked assignment in Tasks updates its Course Workspace immediately after the snapshot reloads.
- Separate planned and deadline dates remain unchanged by rescheduling. Calendar markers visually distinguish planned work from hard deadlines.
- Drag an unfinished scheduled or unscheduled task onto another date in the Calendar on desktop, or edit the planned date on mobile.
- Tasks can now be created from the global Tasks screen and optionally linked to an active course/week, including revision, reading, notes, or assignment activities.
- Personal/study tasks support repeat rules: none, daily, weekly, monthly. The current behavior is **repeat after completion** (one next scheduled occurrence is created when you mark an item complete). No background jobs or infinite backlog generation.
- Existing Firestore documents need **no migration**: new recurrence fields are optional/defaulted in the Pydantic and TypeScript models.
- Existing v0.4 Preview/Production Firebase isolation checks remain untouched.

## Repeat design and limits

- A repeated item requires a planned date. Assignment items cannot repeat.
- Completing a repeated item creates a next instance with a stable deterministic ID, preserving its due-date offset. Repeated completion requests cannot create duplicates.
- It does not retroactively fill missed days or generate future calendar instances when a task is left incomplete. To stop a series, set **Does not repeat** on the next active task.
- There is no notification or Google Calendar integration yet. No timed recurring scheduler is running when the site is closed.
- Date inputs are local calendar dates (`YYYY-MM-DD`); there are no event times in v0.5 so timezone conversions are not required for scheduling.

## Test commands

From `backend/`:

```sh
python -m pip install -r requirements.txt pytest
python -m pytest -q
```

From `web/`:

```sh
npm install
npm run lint
npm run build
```

The backend tests and TypeScript syntax parse were executed in the source environment. A complete frontend dependency install/build must pass GitHub Actions before merge.

## Preview acceptance checklist

1. Confirm latest `main` contains v0.4 and the v0.5 branch was created from it.
2. Check GitHub Actions: API tests, TypeScript check, Next.js build.
3. Preview uses the **Preview Firebase project**, never the production service account or Drive secrets.
4. Create a personal task with a planned date and separate due date. Confirm it appears in Today or Upcoming as expected.
5. Create a course-linked revision task in Tasks, check Course Workspace, mark complete from either screen, verify same status.
6. Open Calendar and click dates. Verify separate `plan` and `due` indicators and selected-day agenda.
7. Move a task by drag-and-drop and confirm **planned date changes but due date stays identical** after refresh. Use the Edit date field on mobile.
8. Add a daily/weekly repeat, complete it and confirm **exactly one** new occurrence. Recomplete the old task and verify no duplicate.
9. Archive a course and confirm its tasks disappear from active Tasks; restore it and verify tasks return.
10. Refresh, sign out and back in; confirm saved task state persists. Check phone-size layout and browser console.
11. Confirm Production data has not changed before merging.

## Release procedure

When acceptance tests pass, merge the `feature/v0.5-tasks-calendar` PR into `main` and check Production. Do not tag v0.5 until Production and the Google Drive PDF workflow are reverified.
