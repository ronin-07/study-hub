# Study Hub v0.5 — targeted performance audit

## Source baseline

Built on the previously delivered `studyhub-v0.5-shared-sidebar-local-clock.zip` and the v0.5 backend. This is a **changed-files package**, not a complete repository. Apply only to the existing `feature/v0.5-tasks-calendar` branch after checking for newer commits. No secrets, Firebase rules, or data migrations were changed.

## Findings and fixes

| Path | Previous behavior | Optimized behavior |
| --- | --- | --- |
| Checking a task | Wait for PATCH, then fetch the full `/api/snapshot` (six collections) before updating UI | Update checkbox immediately; PATCH just one document; reconcile with returned item; rollback with an error if write fails |
| Recurring completion | PATCH plus full snapshot | PATCH plus items-only GET to load generated successor; no rollback if the write succeeded but the follow-up read fails |
| Task create/edit/delete, course week/resource edits, Focus control | Full snapshot after each action | Update the relevant in-memory collection from the API response (or remove the deleted record) |
| Course rename | Scanned weeks, items and resources to check out-of-range weeks on every rename | Scan those three collections **only when reducing** `week_count` |
| Initial snapshot | Six synchronous Firestore `stream()` calls inside an async endpoint | Six concurrent, threaded collection reads (SQLite remains sequential) |
| Firebase authorization | Synchronous revoked-token verification could block other requests | Offload unchanged `check_revoked=True` verification to a worker thread; authorization policy unchanged |
| Browser-tab return | Could refetch six collections on each return | Auto-refresh only when the last successful full snapshot is at least 30 seconds old; manual Refresh always available |
| Header clock | Re-rendered whole page every second even when not studying | Refreshes every 30 seconds without a running Focus timer, every second while running |
| PDF reading bookmarks | Every page turn did a server write and locked the global UI | Optimistic local bookmark with a 650 ms debounce; serialized writes; flush on PDF close or tab hide |
| Header avatar and sign-out | Inert avatar; tiny sign-out link | Remove inert avatar; full-width, accessible Sign out action in consistent sidebar footer |

The six collection streams are still required for the initial snapshot. The optimization reduces their *wall-clock dependency* through parallelism but does not reduce the number of underlying collection queries on initial load. Subsequent targeted edits avoid rereading all six collections.

## Timing instrumentation

API responses include the `Server-Timing: api;dur=...` header, which you can inspect under Chrome DevTools > Network > Response Headers / Timing. It measures server-side processing, including authentication and Firestore operations; compare it with the full browser request duration to distinguish backend cost from network latency.

No fabricated milliseconds or production-speed claims: the current environment cannot reach your Vercel Preview Firebase instance.

## Release checks (Preview Firebase only)

1. **Fresh login:** Home loads once. A refresh and switching browser tabs do not repeatedly trigger snapshots within 30 seconds.
2. **Task completion:** Home, Course Workspace and Tasks checkboxes respond immediately. Refresh afterward; the saved completion remains. Disconnect the network and retry: completion rolls back with a visible error.
3. **Recurring tasks:** Completing a weekly task produces exactly one future occurrence, including after refresh.
4. **Task CRUD:** Create, edit, delete, reschedule and drag/drop dates. Refresh after each and verify the server agrees.
5. **Course workspace:** Add and rename a course, edit a week, archive/restore a course; verify changing to a shorter week count still rejects invalid data.
6. **Resources:** Link/unlink a course resource; open a PDF and turn pages quickly; close/reopen and check the last saved page.
7. **Focus:** Start, pause, resume, finish, reload and confirm sessions persist and total focus hours update.
8. **Account and UX:** Avatar removed from top bar; Sign out visible in the sidebar. Verify auth isolation, both themes, narrow/mobile layouts.
9. **Cloud diagnostics:** Compare `Server-Timing` and total duration for `/api/snapshot` and a single `/api/items/{id}` PATCH. Verify no repeated snapshots after ordinary non-recurring checkbox clicks.
10. **Production gate:** `npm ci`, `npm test`, `npm run lint`, `npm run build`, backend `python -m pytest -q`, GitHub Actions and Vercel Preview smoke tests all pass before an approved merge.

## Remaining considerations

- Server-side Firebase token **revocation checks remain enabled on every request**, a deliberate security choice. They may add latency. Do not disable them merely to improve a benchmark.
- Cross-device sync uses explicit refresh and a visibility-based check, not realtime Firestore listeners. Changes from another device may take up to a refresh to appear; local changes remain immediate.
- As session history grows very large, the unbounded session collection in the initial snapshot is an additional optimization candidate, but paginating history or aggregating analytics requires a separate approved milestone.
- No live deployment or full Next.js build was verified in this environment; the offline npm registry cache is incomplete (`ENOTCACHED`).
