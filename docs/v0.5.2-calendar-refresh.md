# Study Hub v0.5.2 Calendar and refresh

Apply this archive on top of the Stage A PDF and startup changes.

- Calendar keeps its month labels and date counts stable while switching days, dragging tasks, and editing forms. Navigation and date calculations use the workspace already loaded in the browser.
- Startup, manual refresh, and a return to the browser tab share a pending workspace load for the same account and teaching week. The existing 30-second freshness threshold remains. A save that requires reconciliation can replace a read that started before the save.
- A refresh preserves tasks and other records changed locally while the request was pending, including an in-flight Focus update. It still applies unrelated changes from another device. Changing accounts cancels the pending read.

This is a frontend update. It adds no Firebase writes, Firestore reads, subscriptions, rules, indexes, or schema changes. It avoids duplicate snapshot requests when refreshes overlap. A canceled request may already have reached Firestore.

## Local verification

The local-auth production build, TypeScript, and all 212 frontend tests passed. In local Chrome, Calendar month navigation used the existing snapshot, overlapping visibility events shared one request, and a stale snapshot preserved a saved task while applying an unrelated remote edit. The browser run used fixture data.

From the checkout after applying the ZIP, run the following in PowerShell.

```powershell
Push-Location web
npm.cmd ci --no-audit --no-fund
npm.cmd test
npm.cmd run lint
$env:NEXT_PUBLIC_STUDY_HUB_AUTH_MODE = 'local'
$env:NEXT_PUBLIC_API_URL = '/'
npm.cmd run build
Pop-Location
```

In Preview, open Calendar on a laptop, switch months, choose a day from Home, and drag or reschedule a task. Verify that planned and due counts stay correct and that the saved date appears in Tasks. In Network, check that Calendar navigation alone creates no snapshot request. With a slow snapshot underway, switch tabs a few times and confirm the browser shares that request. Check that a task changed during refresh stays changed and a separate edit from another browser appears on a later refresh.
