# Study Hub v0.5.2 — Polish 1 production corrections

Corrects three reported visual/behavior regressions from the first Home + Study polish. Apply **on top of** the deployed v0.5.2 Polish 1, staying on `feature/v0.5.2-final-polish`.

## Changes

1. **Exam Prep:** Progress uses canonical `progressItems` so a completed exam task shows `1/1 completed` even while the checkbox completion animation holds the display row. Completed rows use a lighter, calmer highlight. When editing a course-wide Exam Prep task, its Activity type displays **Exam preparation**, not a confusing generic Revision. The stored value stays `kind: revision`, `week_number: null` for backward compatibility; weekly Revision activities stay separate. No migration or backend contract change.
2. **Study Tasks menu:** Replaces the clipped in-card `<details>` menu with a small portal-based menu that flips above the button near the viewport bottom, closes on outside click, Escape, scroll and resize, and exposes keyboard-focusable action buttons.
3. **Home:** Progress counts only work planned/due today within each course, even when the activities come from different teaching weeks. Completing a task preserves it in the day's progress denominator (`0/2` → `1/2` → `2/2`), while course/week totals remain on Study. Overdue-only groups display catch-up progress. The Open course button restores that course's last selected teaching week from existing local storage; missing/invalid values default to Week 1, with the course's maximum week honored. Explicit task/weekly shortcuts still open their target week.

## Manual acceptance checks

1. In Exam Prep, check off one of two tasks and confirm the total and progress bar advance immediately; refresh and confirm the value remains correct. Uncheck one to verify decrement.
2. Open Edit on a course-wide exam task. The Activity type must read **Exam preparation**. Save an innocuous edit and confirm the item still appears in Exam Prep and Global Tasks. A weekly Revision activity should still show **Revision**.
3. With five or more Course Study Tasks, open the three-dot menu on the final row, then a middle row. Menus must be fully visible and usable (including near the bottom of the viewport). Verify Escape, outside-click, scrolling, and tab-key handling. Use a throwaway task for destructive menu actions.
4. Plan exactly two course tasks for today from **Week 1** and **Week 4**. Home must show **Weeks 1, 4**, **2 activities today**, and **Today's progress 0/2**. Complete one in Tasks or Study; Home must show `1/2`, then `2/2` after the second, even after refresh. Future or unscheduled checklist items must not increase the denominator.
5. In Study, choose Week 3 of a course, navigate Home, then click Open course. It must open Week 3. With no saved week for a new course, Open course must open Week 1. Verify switching courses preserves each course's own last week.
6. Test wide monitor and laptop spacing; no menu clipping, no horizontal overflow, both themes. Verify normal PDFs, task completion synchronization and Focus shortcuts.
