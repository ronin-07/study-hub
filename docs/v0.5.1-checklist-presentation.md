# Study Hub — Post-v0.5.1 Checklist Presentation Polish

## Approved design implementation

- **Study / Weekly learning checklist:** full activity view with title, contextual status, question/chapter/section reference, optional pages, planned and due dates, named PDF link, expandable notes, and four existing actions (edit, plan, focus, delete). Checkbox remains the single shared activity completion action. No redundant standalone type label when the reference identifies the type; `Checklist only` shown for activities not included in Tasks.
- **Tasks:** compact summary with title, course/week, the learning reference, most relevant date, and existing Edit/Resource/Focus actions. Expand `More details` to see secondary fields, including pages, other date and notes.
- **Calendar:** month cells retain the existing count markers. The selected day agenda starts with title, course/week and planned/deadline context, with optional expanded details. An activity planned and due on the same day occurs once in the selected-day agenda and is explicitly marked **Planned and due**.
- **Home:** task summaries remain minimal; show a question/chapter reference only when supplied, preserving existing completion, navigation and Focus actions.

The presentation helpers in `web/lib/activity-display.ts` do not write or mutate stored records. Numeric references retain their dots, commas are spaced only when displayed, and calendar dates remain local date-only strings.

## Local build and Preview checks

From the repository root:

```bash
cd web
npm ci
npm test
npm run lint
npm run build
cd ../backend
python -m pytest -q
```

Manual checks in Preview or carefully using disposable Production records:

1. Study → course → week: compare four activity types (Questions, Reading, Lecture, Notes) plus an Assignment. Title, references (`1, 2`, `3.5, 3.11`, `4.2.1`), page ranges, planned/due dates and filename should be readable without duplicate activity kind text.
2. Expand a long Notes field and collapse it. Open an existing linked Google Drive PDF; verify correct document opens, not just a generic resource link.
3. Check `Today`, `Overdue`, `Plan missed`, `Completed`, and `Checklist only` states. Ensure no badges overflow at narrow widths.
4. Edit, plan, Focus, complete, and delete a disposable activity; verify persistence and course completion totals.
5. Toggle `Include in Tasks and Calendar`: verify Study retains the record, Tasks/Calendar/Home visibility responds and the item restores without losing progress.
6. Tasks: the default row shows course/week, reference and one relevant date; expand `More details` for pages and notes. Confirm actions and recurring personal tasks remain functional.
7. Calendar: verify planned and due records on different dates, a record with both dates the same day (only one agenda row, labeled `Planned and due`), and drag-to-reschedule restrictions.
8. Home: confirm Today priorities and course cards show short references, correct dates/status, and navigation to the same underlying activity.
9. Refresh, use another tab, test light/dark themes and laptop/mobile widths. Confirm no data resets or action overlap.
10. Verify frontend and backend Vercel deploy successfully and Preview points to its own Firebase project.
