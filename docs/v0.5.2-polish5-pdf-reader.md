# Study Hub v0.5.2 — Polish 5: PDF Reader and final corrections

## Scope

- Native PDF reader retained; no PDF.js replacement, API schema change, or change to the underlying Drive file IDs.
- `Preview` now opens a filename-specific loading dialog immediately, before authentication and the file download complete. The indicator is indeterminate (not a fake percentage).
- A dedicated PDF request coordinator cancels obsolete downloads and ignores stale results. Repeated clicks for the same in-flight PDF are ignored; the newest different file wins. Unused object URLs are revoked, including on close and sign-out.
- A 120-second download timeout, explicit cancellation, recoverable error and Retry action are provided. A notice appears when a download takes longer than 20 seconds.
- The browser PDF iframe has a separate "preparing" state, Retry Viewer and Close actions. Frame loading does not report invented progress.
- Duplicate Study Hub zoom controls and the large guidance banner are removed; Chrome's native PDF toolbar continues to provide PDF search, zoom, download and print. Study Hub keeps explicit saved-page navigation and a collapsible Study Mode sidebar.
- The profile name tooltip renders above all sidebar clipping via a viewport-aware portal. The sidebar collapse button has a larger target and less crowding.
- Focus and Resources input focus outlines share one sage-green, rounded treatment. Brand/mauve selection and semantic completion colors remain unchanged.

## Acceptance tests — run with a real Google Drive account

1. With the Resources PDF list visible, click Preview once on a 500+ page textbook. A loading screen must appear immediately with the exact filename; the PDF must open when downloaded.
2. Click Preview repeatedly. A single in-flight request should remain. Close while opening; no PDF should appear later. Try selecting a different file rapidly, if possible; only the latest one may appear.
3. Disconnect the network temporarily or simulate a failing PDF response. Expect an error state and a Retry button. Cancel and Close should return to the previous Resources page, without a stale PDF opening.
4. Open an original PDF uploaded to Google Drive. Confirm that embedded external hyperlinks and internal table-of-contents links work in Chrome's native viewer. A flattened Goodnotes backup may not contain working links; this cannot be fixed by the viewer.
5. Check that Chrome's native PDF toolbar still searches, zooms, prints and downloads. Study Hub's top toolbar should not duplicate zoom.
6. Use the Saved page control, close and reopen the same linked document; it should open on the stored page. Native manual scrolling does **not** save the bookmark automatically.
7. Collapse and reopen Study Mode. Confirm the book has more room, the checklist and Start Focus remain functional, and other resource links open the correct document.
8. On the sidebar, hover or keyboard-focus the truncated profile name. The complete tooltip must be visible and not clipped. Toggle expanded/icon-only sidebar and resize it.
9. Focus the Resources search and Focus review inputs with keyboard and mouse. Expect exactly one sage-green outline with comfortable padding.
10. Repeat the viewing and form checks on a laptop, 2560×1440 monitor, and iPhone Safari, in both themes.

## Production impact

- Firestore Auth/rules/indexes: no changes.
- Existing document storage, resource associations and data schema: no changes or migration.
- Google Drive scopes and backend routes: unchanged. Browser PDF download remains an authorized request to the existing `/api/drive/files/{id}/pdf` endpoint.
- Vercel environment variables: no changes. A frontend deployment is needed after the local build passes.
- Browser native PDF hyperlinks require annotations in the source PDF; use original textbooks rather than flattened Goodnotes backups for linked chapters.
